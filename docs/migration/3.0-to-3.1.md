# Migrating From 3.0 to 3.1

Desktop Updater 3.1 removes the old direct release-signing command model. The
3.0 direct environment/file signing commands are removed in 3.1; they are not
deprecated and there is no compatibility layer.

## New project

Create the feed-bound profile once:

```sh
dart run desktop_updater:release keygen
```

Then use the profile-backed commands:

```sh
dart run desktop_updater:release publish --platform macos
dart run desktop_updater:release sign --release dist/desktop_updater/releases/3.1.0/macos/release.json
dart run desktop_updater:release validate --manifest dist/desktop_updater/.desktop_updater_publish.json
```

The public `desktop_updater.keys.json` file may be reviewed and committed. The
private seed remains in the protected local key store. Use `--key-profile` when
the profile is not at the project default path.

## Existing feed

If a feed already uses a manually selected key ID, adopt the existing key once.
The protected input is strict JSON with exactly these fields:

```json
{
  "schemaVersion": 1,
  "keyId": "stable-2026",
  "privateSeed": "<base64-raw-32-byte-ed25519-seed>",
  "publicKeys": {
    "stable-2026": "<base64-raw-32-byte-ed25519-public-key>"
  }
}
```

Run adoption from a protected machine, with a passphrase supplied through the
passphrase mechanism or an interactive terminal:

```sh
dart run desktop_updater:release keys adopt \
  --input legacy-adoption.json \
  --output release-key.dukey \
  --passphrase-env DESKTOP_UPDATER_BUNDLE_PASSPHRASE
```

Adoption preserves the existing key ID, validates that the private seed matches
the selected public-map entry, writes the new feed-bound profile, and exports
an encrypted key bundle. It does not sign a release directly. After successful
export, delete the plaintext `legacy-adoption.json` input. CI and other
machines must import only `release-key.dukey` and must never receive a raw
private key through an environment variable or file.

```sh
dart run desktop_updater:release keys import \
  --input release-key.dukey \
  --passphrase-env DESKTOP_UPDATER_BUNDLE_PASSPHRASE
```

The imported profile must match the configured feed and public-key map. A
missing profile error points to `release keygen` for a new feed or this
one-time adoption flow for an existing feed.

## Verification

`release validate` and standalone `verify` use the same public profile. Use
`--candidate-only` only for explicitly unsigned local candidates; it is not a
production trust result.
