# Full Native Runtime Preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add preview native runtime APIs for non-Flutter macOS, Windows, and
Linux apps that match the current `desktop_updater` 2.7 discovery, trust,
download, verification, staging, artifact, and policy contracts.

**Architecture:** Flutter apps continue to use the Dart `UpdateClient`. Native
runtime targets live beside the helper SDKs but are separate build targets, so
Flutter plugin builds do not acquire native HTTP, archive, JSON, or crypto
dependencies. Swift and C++ implementations consume Dart-generated golden
fixtures and hand already verified/staged artifacts to the helper APIs produced
by the master plan.

**Tech Stack:** Swift/CryptoKit/Foundation, C++/CMake, Windows WinHTTP and
BCrypt, Linux libcurl and OpenSSL SHA-256, a pinned portable Ed25519 verifier
for Windows/Linux runtime targets, safe archive readers, XCTest, GoogleTest,
.NET P/Invoke, and schema-v3 contract fixtures generated by Dart.

work from the master plan.

## Preview Boundaries

- Do not replace Flutter's Dart runtime.
- Do not change schema version 3.
- Do not hand-write release fixtures; regenerate them from the Dart contract
  generator.
- Do not document a native runtime API before its target-host tests compile it
  from an external consumer project.
- Do not mark the runtime production-ready until every platform has an
  end-to-end non-Flutter update smoke.
- Do not silently fall back from an unsupported artifact kind to ZIP. Return a
  typed unsupported-kind error before download.
- Require expected package identity from the native application.
- Bind the selected index item to descriptor version, integer build number,
  platform, and channel.
- Treat `app-archive.json` as discovery metadata, not signed metadata.
- Verify descriptor Ed25519 signatures with Dart-compatible canonical bytes
  and a pinned `publicKeyId`.
- Apply `minimumUpdaterVersion`, `minimumOS`, rollout, support-policy, and
  fresh-install behavior before download/install.
- Preserve current platform publisher checks for DMG, PKG, and Inno artifacts.
- Use only the validated Linux install target from the master plan.
- Keep helper JSONL event names and diagnostics redaction compatible.

## Required Artifact Capability Matrix

The preview is not complete until these combinations work:

| Platform | Artifact | Staging/install path |
| --- | --- | --- |
| macOS | `zip` | safe `ditto` extraction, app validation, helper whole-bundle replacement |
| macOS | `dmg` | primary-signature validation, read-only mount, exact app copy, app trust validation, helper replacement |
| macOS | `pkgInstaller` | package signature/Gatekeeper/stapler/package-ID validation, Installer.app handoff |
| Windows | `zip` | safe directory staging, manifest, helper directory replacement |
| Windows | `innoInstaller` | Authenticode policy, manifest, helper installer execution |
| Linux | `zip` | safe directory staging and validated self-contained install-root replacement |

## Native Runtime Dependency Policy

- macOS uses Foundation/URLSession, CryptoKit SHA-256 and Ed25519, and existing
  system tools already required by the Dart runtime for ZIP/DMG/PKG handling.
- Windows uses WinHTTP for transport and BCrypt for SHA-256.
- Linux uses libcurl for transport and OpenSSL for SHA-256.
- Windows and Linux use Monocypher 4.0.3 plus its optional Ed25519 source,
  compiled only into native runtime targets. Pin the official archive:

```text
https://monocypher.org/download/monocypher-4.0.3.tar.gz
SHA-512 40904ada5c7ee4f7741733e38b69a30a4b0561cbffba5ffe7c2dce16136d540251ec0d9056ff606510d3b5b708fb8a40db7e0870d4a0b2dc17ba2bfb880f8965
```

Retain the CC0/2-clause-BSD licensing files, run the upstream tests, and pass
the repository's canonical Ed25519 fixtures. If security review rejects this
dependency, this plan returns to `blocked`; do not substitute a different
algorithm or unreviewed implementation.
- Windows and Linux ZIP runtime targets use miniz 3.1.2 from the official
  release asset:

```text
https://github.com/richgel999/miniz/releases/download/3.1.2/miniz-3.1.2.zip
SHA-256 f0446d863f9c19926ad9483c523fdc42e42b8d4a6a431d27e09d49c79a140d9a
```

Compile miniz only into runtime targets and validate every central-directory
entry against the shared safe-path fixtures before extraction.
- Runtime archive/crypto sources are not linked by helper-only Flutter builds.
- Every third-party source or binary records version, source URL, checksum,
  license, build options, and whether it is statically or dynamically linked
  in `third_party/README.md`.

- [ ] **Step 4.1: Match supported URL policy**

Accept absolute `https`, `http`, and `file` URLs. Reject missing schemes,

- [ ] **Step 4.2: Add request headers and timeout**

Call the app-owned header provider for index, descriptor, release notes when
used, and artifact requests. Redact header values from diagnostics.

Use system TLS trust. Reject certificate-validation bypasses and HTTPS-to-HTTP
redirect downgrades. Limit redirects to five. Re-evaluate app-owned headers for
the redirected URL and do not forward authorization across hosts unless the

- [ ] **Step 4.3: Match retry and partial-file cleanup**

- server ignoring range and returning full `200`;

- [ ] **Step 4.4: Prevent unbounded downloads**

## Task 5: Safe Staging And Artifact Matrix

**Files:**

- Create: platform artifact stagers and tests
- Modify: helper handoff adapters
- Consume: generated safe-path and release-contract fixtures

- [ ] **Step 5.1: Enforce safe archive paths**

Reject before write:

- `..` traversal;
- absolute paths;
- Windows drive prefixes;
- symlinks and hard links;
- entries whose canonical destination escapes staging;
- duplicate file/directory type conflicts.

Preserve executable permission metadata on Linux. macOS ZIP staging uses
`ditto` and then rejects a top-level app symlink.

Before extraction, enforce `maximumArchiveEntries`,
`maximumUncompressedBytes`, and `maximumSingleEntryBytes` using 64-bit checked
addition. Exceeding a limit returns `unsafeArchive` and removes the partial
staging directory.

- [ ] **Step 5.2: Stage macOS ZIP**

Extract with `ditto`, locate the exact `.app`, verify bundle identifier, Team
ID, codesign, Gatekeeper, and stapler policy, then write the staged release
manifest before calling `MacInstallHelper`.

- [ ] **Step 5.3: Stage macOS DMG**

Verify the DMG primary signature when required, mount read-only/no-browse,
locate exactly the configured app bundle, copy it out, detach on every path,
verify the copied app, and hand it to the whole-bundle helper.

- [ ] **Step 5.4: Stage macOS PKG**

Verify package signature, Gatekeeper install assessment, stapler ticket, and
expanded package IDs. Stage `installer.pkg` plus the release manifest, then
use the helper's Installer.app handoff.

- [ ] **Step 5.5: Stage Windows ZIP and Inno**

ZIP staging rejects unsafe entries and writes the manifest. Inno staging
verifies Authenticode requirements and allowed signer thumbprints, writes
`installer.exe` plus the manifest, and passes the complete request to the
versioned helper C ABI.

- [ ] **Step 5.6: Stage Linux ZIP**

Stage only a self-contained directory bundle. Verify the staged executable
relative path and package identity, then pass the explicit validated
`install_root` contract to the Linux helper. Never infer `/usr/bin` or another
shared directory as the app root.

- [ ] **Step 5.7: Run artifact tests**

Run all unit tests and target-host platform trust tests. DMG/PKG/Inno tests
that require signing credentials remain `blocked` until explicit credentials
and approved workflows are available.
